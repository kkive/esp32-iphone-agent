# 实时视频转发修复（测试版）

基于 ESP32 iPhone Agent by Henry Yuan，保留原项目 LICENSE/NOTICE。

## 变化

- 实时视频使用独立的 96 项、总有效负载最多 768 KiB 的 PSRAM 队列。
- GOP 缓存继续用于截图及追帧；其溢出不再中止已经同步的实时帧链。
- 追帧记录原子快照的帧序号，实时队列跳过已重放帧，避免重复或漏掉依赖帧。
- 内存不足、队列满、发送失败、编码参数更新、传输路径切换会撤销同步状态。
- 失去同步后，仅从完整 GOP 或真实 IDR 重新开始；不把普通 P 帧伪装成关键帧。
- App 发现板子需要重新同步时清除旧画面，并在模型返回后再次检查画面状态。

诊断中的“等待关键帧”现在表示实时接收端需要同步，而不只是历史 GOP 失效。
“缓存溢出次数”仍保留原始缓存计数。溢出后该计数增加，但实时画面应继续更新。

## 规划开关

设置 → 任务 → 提前规划任务，默认开启，保留原行为。设置会保存到本机。
关闭时不调用规划模型，执行请求不包含 Plan 段，输入为任务、最近操作、当前截图。
任务开始时读取该设置，运行过程中禁用切换。发生错误后也不偷偷开启规划。

## 验收（尚需真机）

1. 启动镜像，运行任务并持续操作足够长时间，观察 GOP 溢出计数增加。
2. 确认画面和解码帧率继续更新，结束任务后立即及等待数分钟后分别启动第二个任务。
3. 前后台切换，测试 App 解码器恢复。
4. 分别测试停止视频、Wi-Fi 断开、重新配对等真正失去帧链的情况。
5. 对没有新 IDR、且已经丢失完整 GOP 的冷启动，仍可能需要重新开始镜像。
   本改动不声称实现了强制 iPhone 生成 IDR，也不保证所有重连场景自动恢复。

该版本需要更新固件和 App。不要使用全量镜像覆盖已有配对配置；兼容分区下只写应用区域。
